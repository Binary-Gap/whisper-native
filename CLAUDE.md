# whisper-native

Native macOS Swift port of the Hammerspoon whisper dictation tool: always-on menu-bar agent that records mic, transcribes via a local whisper.cpp server daemon, and inserts text into the focused app.

## Architecture
- Menu-bar agent app (`LSUIElement=true`, no dock icon). SwiftUI `@main` + `AppDelegate`. App target `WhisperNative`, bundle id `io.binarygap.whisper-native` (Binary Gap LLC).
- Dev app: the Debug config builds "WhisperNative Dev" (`io.binarygap.whisper-native.dev`, project.yml `configs.debug`), so it runs next to the installed Release copy in `/Applications`. Separate bundle id = separate TCC grants, UserDefaults (settings, hotkeys, onboarding) and menu bar item. `Constants.isDevBuild` (`#if DEBUG`, so tests get the dev values too) splits the rest: daemon label `io.binarygap.whisper-server.dev` on port 8081, data `~/Library/Application Support/whisper-native-dev/` (history, tmp, calibration), logs `~/Library/Logs/whisper-native-dev/`, Keychain service `io.binarygap.whisper-native.dev.gemini`. The models folder (`whisper-native/models`) is shared. Paths and names elsewhere in this file are the Release values. Both copies start with the same default hotkeys, so while both run give the dev app its own toggle hotkey.
- Built with xcodegen (`project.yml` is source of truth; `WhisperNative.xcodeproj` is generated + gitignored). Tasks via mise.
- Pipeline: global hotkey -> `AudioRecorder` (AVAudioEngine -> 16kHz mono 16-bit PCM wav) -> `WhisperClient` (HTTP multipart POST to local server) -> `TextInserter` (pasteboard+Cmd-V w/ restore, CGEvent typing fallback). Orchestrated in `Sources/WhisperNative/App/`.
- Whisper server is an always-on DAEMON, not a child process: `WhisperServerManager` installs a launchd plist and `launchctl bootstrap`s it. Server stays up between dictations while the app runs (warm model = the whole point). The plist has KeepAlive + RunAtLoad, so it respawns and starts at login until booted out + disabled: switching to another engine, the Start/Stop toggle and quitting do that. Quit (menu, logout, or SIGTERM from `pkill`, which a DispatchSource turns into `NSApp.terminate` through a `RunLoop.main.perform`, since the quit reply needs the main queue the handler runs on) boots it out in `applicationShouldTerminate` while Whisper is the engine, waiting at most 3 s for launchctl.

## Modules
Source dirs group by target under `Sources/<target>/<module>/`. App target (`WhisperNative`): App, Hotkeys, Settings, Onboarding. Framework target (`WhisperNativeCore`): Shared, Server, Backend, Audio, TextInsertion, UI. This mirrors the two-target split and renders as two parent groups in Xcode.
- Shared: Models, Config (UserDefaults-backed, all settings), Constants (paths/ports), AppError, FileLogger, ProcessRunner (every child process: `launchctl`, the iTerm2 helper, `mise which`; drains stdout/stderr while it runs, kills it at a per-call timeout).
- History: `TranscriptionHistoryStore` writes `~/Library/Application Support/whisper-native/history/history.json`, the newest `Constants.maxHistoryItems` (5000) dictations kept as a usage log for debugging and model comparisons (text, language, model, timestamp, response time `durationSeconds`, `audioDurationSeconds`, Gemini Live mode `transcriptionMode` (nil for other engines and for reruns, which go through the batch model and record `GeminiBackend.modelID`), `estimatedCostUSD` (Gemini models only, nil for local engines: `GeminiPricing` list price x 25 audio tokens/s in + transcript chars/4 out, since Live never reports usage; a rerun replaces it with the rerun's cost; failed batch runs aren't billed, failed Live runs are)); only the newest `Constants.maxHistoryAudioFiles` (50) entries keep their WAV, older WAVs are deleted on the next add. The History window lists the newest `maxHistoryDisplayedItems` (100) matches; search runs over all entries. While a whisper model downloads, the History window shows its progress under the search field (`ModelDownloadBanner`), since it is the window open when the first-run download starts.
- Server: WhisperServerManager (launchd bootstrap/bootout, health, model hot-swap via POST /load), LaunchdManager, ServerPlist, ModelManager (whisper catalog with sizes + hints, folder scan, download), WhisperServerDisplay (server pill text/tone, Start/Stop disabled reason, `WhisperModelPreparation` plan), ModelStorage (model rows' downloaded / in-use / size / delete rules for every engine).
- Backend: WhisperClient + TranscriptionBackend protocol, MultipartFormData. WhisperClient's `prompt` field comes from `WhisperPrompt` (Core): the per-language example sentence (`Constants.languagePrompts`, en/pt only), then the Settings > Whisper "Initial prompt" text (`Config.prompt`), then, while `Config.whisperUsesVocabulary` is on (default on, "Use custom vocabulary" toggle on the Whisper page), the words file's `vocabulary` terms for the selected language (same selection as Gemini: `all` + its list, auto every list), read at every request through `WordsFile.load`, as one `A, B, C.` sentence. whisper.cpp keeps only the last 224 prompt tokens and drops the start, so the example and the user text stay whole and terms are added in file order (stopping at the first that doesn't fit) while the estimated size (`WhisperPrompt.estimatedTokens`: ASCII 3 characters per token, any other character 1 token) stays within 200; the rest are left out and a warning is logged. Parakeet has no custom vocabulary (a secondary line on its page says so). ParakeetBackend (`.shared` actor): Parakeet TDT v3 in-process via the FluidAudio SPM package (Apache-2.0, pinned `exactVersion` in project.yml), Silero VAD first, output through FillerRemover (drops uh/hmm; "um" only for non-Portuguese text since it's the pt article). "Wrap lines" / "Sentence per line" apply to Parakeet too: whisper wraps server-side (`max_len`), Parakeet through `LineWrapper`. Models download to `~/Library/Application Support/FluidAudio/Models` on first load (~20s first load, then ~0.05-0.5s per dictation); Settings > Parakeet can also download either model alone without loading it (`ParakeetBackend.download(_:)`, speech model with byte progress) or delete it.
- Backend (experimental): GeminiBackend (`.shared` actor) sends the finished WAV inline (base64) to `gemini-3.5-transcribe` via `POST v1beta/interactions` with `store: false` (no server-side retention); fixed language goes as a `language_codes` hint, auto sends none. Custom vocabulary (both Gemini engines, and whisper's prompt through `WhisperPrompt`) comes from the words file (`WordsFile`): `words.yml` in the data folder (`Constants.wordsFileURL`, dev: `whisper-native-dev/`), read at every request / recording start, parsed with Yams (SPM, pinned `exactVersion`, linked to WhisperNativeCore). Two top-level sections, `vocabulary` and `stop words` (key case-insensitive; other top-level keys, repeated sections and a section holding anything but keys log a warning and are ignored, so an ignored stop words section means the defaults); each maps `all` (every language) or a language by English name (case and diacritic insensitive, `Portuguese`) or whisper code (`pt`) to a list of terms; unknown keys and nested values log a warning and are ignored, an empty key is an empty list, an empty section (no value, `[]`, `{}`) has no terms. A fixed language uses `all` plus its list, auto every list; terms are trimmed and exact duplicates dropped; vocabulary sends the first 1,000 (warning logged above that). Without a `stop words` section (or file) the defaults apply (`WordsFile.defaultStopWords`: `all: [over]`, `Portuguese: [câmbio]`). Non-empty vocabulary goes as `transcription_config.custom_vocabulary` (Live: `inputAudioTranscription.customVocabulary`), an empty list omits the field. Malformed YAML logs a warning, sends no vocabulary and uses the default stop words. When `words.yml` is missing it is migrated once from the older files, which stay on disk unused: `vocabulary.yml` (language keys at the top level) becomes the `vocabulary` section (text indented under the key, terms and comments kept, its old header and keys comment dropped), else the one-term-per-line `vocabulary.txt` goes under `vocabulary: all:`; the default `stop words` section is written after either. Settings > Gemini and Settings > Whisper show the `vocabulary` section in a Custom vocabulary section (`VocabularySection`, shared) grouped by key (all languages first) with counts, ignored-key warnings and any parse error; on Whisper it adds the "Use custom vocabulary" toggle on top, dims the terms while it is off, and shows an orange line when the selected language's terms don't all fit whisper's prompt; Settings > Recording > Start and stop shows the stop words in effect. Both re-stat the file every second while visible (`WordsFileModel`, shared by these views) and have an Edit… button that creates the file (header + both sections) if missing, appends a missing section (empty vocabulary `all`, default stop words) at the end of the file, inserts an empty key (English name) for each of the user's languages missing from a section at the end of that section (text insert at the section's key indentation, existing content and comments untouched, skipped where it wouldn't parse, e.g. flow style), rewrites the `# Keys for your languages: Portuguese (pt), …` comment line (added on top if missing), and opens it in the default editor (TextEdit fallback); agents can edit the file directly. Same FillerRemover/LineWrapper post-processing as Parakeet, no live preview, no segments. ~2s per dictation; inline cap ~7 min of audio (20 MB request); key limited to ~10 requests/min. Key in the Keychain (`GeminiAPIKeyStore`, service `io.binarygap.whisper-native.gemini`, edited via `GeminiAPIKeyField` in Settings and onboarding), `GEMINI_API_KEY` env as fallback; never in Config or logs. `GeminiKeyModel.shared` (app target) publishes `GeminiKeyStatus` (Core: missing / Keychain / environment) to every view that depends on it; the key field shows it as a status line, saves on Return, Save or focus loss with a brief "Saved" mark (`GeminiKeyFieldCommit` decides unchanged / save / confirm removal), and asks before deleting the Keychain key (clearing the field or Remove Key…; leaving the page with a cleared field keeps the key). Gemini can't be activated without a key: the General picker entry, the onboarding radio and "Use Gemini" are disabled with the reason shown. A key removed while Gemini is active leaves Gemini selected (no silent engine switch): orange warnings on General, the Gemini activation row and the key field, and each dictation fails with `AppError.geminiAPIKeyMissing`. Live test `GeminiBackendTests.testLiveTranscriptionOfSpokenWav` runs only with the key plus `GEMINI_BILLED_TESTS=1` (`BilledGeminiTests.apiKey()`; every other test uses stubs and never reaches the network): pass `TEST_RUNNER_GEMINI_BILLED_TESTS=1 TEST_RUNNER_GEMINI_API_KEY=<key>` to `xcodebuild -scheme WhisperNativeCoreTests -configuration Debug test -only-testing:WhisperNativeCoreTests/GeminiBackendTests`. Every Gemini call is billed: no exploratory or repeated API requests (list-models, retries, reruns of the live test) unless the change touches the request path; answer API questions from docs or earlier responses first.
- Backend (experimental): Gemini Live streams audio while recording to `gemini-3.5-transcribe-live` over the Live API WebSocket (`BidiGenerateContent`, key in the `x-goog-api-key` header so the URL is loggable). `GeminiLiveProtocol` (message encode/decode, whisper code -> BCP-47 hint: auto sends `[]`, a fixed language its code with the system region's variant when Gemini lists one, e.g. pt -> pt-BR/pt-PT, languages Gemini lacks send `[]`), `GeminiLiveSession` (one socket per dictation, serial queue: connect + setup at recording start with manual VAD, PCM buffered until `setupComplete` then `activityStart` + 100 ms chunks, stop sends `activityEnd` and waits for the finals + `generationComplete`; the server sends no `turnComplete`; the client closes with 1000 right after generationComplete since the server never closes on its own or sends anything after it, and the API dashboard counts every such client-ended stream as a 409 ABORTED, which is expected and harmless), `GeminiLiveBackend` (5 s final timeout; on connect error, socket drop, timeout or no key it falls back to ONE batch `GeminiBackend` call on the WAV; cancel closes the socket with no activityEnd and no fallback; same post-processing via `GeminiBackend.postProcess`). Interims are cumulative per segment and drive LiveTranscriptPill. `AudioRecorder.pcmSink` hands the tap's converted buffers to the session (the WAV still gets them all). Text style setting `Config.geminiLiveMode` (Smart cleanup default / Verbatim) on the Settings > Gemini page, right under Delivery and only while Live is chosen; `Config.prompt` is unused. Language is fixed at recording start (cycling mid-recording reaches only a fallback call). One log line per dictation: openMs, setupMs, stopToFinalMs, audioSeconds, interim/final counts, fallback yes/no + reason. Debug builds also log `Gemini Live usage:` (mode, prompt/response/thoughts tokens, estimated USD at list price) if `usageMetadata` arrives before the socket closes (this model has never sent it, so Live cost is estimated from audio seconds) and any unhandled server message keys; Release logs neither. History rerun uses the batch model. Live test (billed, run only when the streaming path changes): pass `TEST_RUNNER_GEMINI_BILLED_TESTS=1 TEST_RUNNER_GEMINI_API_KEY=<key>` to `xcodebuild -scheme WhisperNativeCoreTests -configuration Debug test -only-testing:WhisperNativeCoreTests/GeminiLiveSessionLiveTests`.
- Engine switch (`Config.transcriptionEngine`, Settings > General or the "Use …" button on an engine page): General and onboarding offer the three sidebar engines by plain name (`EngineChoice`: Whisper, Parakeet, Gemini; one-line trade-off and technical details behind "?"), Gemini selecting Gemini Live or batch Gemini from `Config.geminiStreaming` (`EngineChoice.engineToSelect`, which also blocks Gemini without a key and keeps the active Gemini engine when re-picked). Selecting Parakeet boots the whisper daemon out and preloads Parakeet; selecting Gemini or Gemini Live boots the daemon out and unloads Parakeet; switching back unloads Parakeet and re-bootstraps whisper. Before that, `AppDelegate.prepareWhisperModel` checks whisper's files (also at launch, on onboarding close and on Start Server): a missing selection is pointed at a downloaded model (`ModelManager.fallbackModel`: recommended, else smallest), a missing VAD model (~1 MB) downloads without asking, and with no whisper model on disk an NSAlert (sheet on the open Settings or History window, else standalone) asks "Download a Whisper model?" naming the recommended model and its size. Download downloads and uses it (`ModelSectionState.downloadDefaults`, status menu shows "Downloading…"); Cancel on a switch from another engine switches back to it (Parakeet stays loaded while the prompt is up), Cancel at launch / onboarding close / Start Server leaves Whisper selected with no model (Whisper page warning, status menu "Model: None downloaded", dictation alert "No Whisper model"). The Settings window never changes page on its own. Parakeet and both Gemini engines skip the whisper health check, prompt and voice calibration. Parakeet auto-detects, and the selected language only picks its script token filter (`ParakeetBackend.tokenFilterLanguage`: FluidAudio-supported language passes through; auto/unsupported gets the Latin filter when the system language is Latin-script, else none).
- Audio: AudioRecorder, WavWriter, RecordingIndicator. AudioRecorder captures through a CoreAudio IOProc (works with Continuity Camera mics) and converts to 16 kHz mono 16-bit for the WAV, `pcmSink` and the listen sink.
- Voice processing (`Config.voiceProcessing`, Settings > Recording > Input, on by default, read at recording start by the Orchestrator and the voice calibration recorder, so the calibration sample matches the dictations it is prepended to): the recording captures through an `AVAudioEngine` input node with `setVoiceProcessingEnabled(true)` (noise suppression, echo cancellation, AGC on), every engine, same converter and routing as the CoreAudio path, so WAV, Gemini Live sink and Parakeet previews all get processed audio. The node reports extra reference channels, so only channel 0 is converted; the selected mic goes on the voice-processing unit after enabling (`kAudioOutputUnitProperty_CurrentDevice`, element 1, warning logged on failure); other-audio ducking is set to `.min` with advanced ducking off (macOS has no zero). Setup failure logs a warning and records the unprocessed CoreAudio mic. Auto-start listening always stays unprocessed (ducking would last the whole idle time, and `SpeechOnsetGate` is tuned on raw levels): `VoiceProcessingPolicy.recordingCapture` keeps the listening capture for voice-started dictations (pre-roll kept) and reopens the mic processed for a hotkey press while listening; Settings shows a secondary line saying so while both are on. Logs one line per processed recording: input format and `Voice processing capture started in N ms, input device X (requested Y)`.
- Auto-start when you speak (`Config.startOnVoice`, Settings > Recording > Start and stop + status menu "Auto-Start When You Speak" + the `toggleStartOnVoice` hotkey, off by default): the menu item and the hotkey share `AppDelegate.toggleStartOnVoice` (flips the setting, confirms with the LanguageHUD pill "ON"/"OFF" over "Auto-start" (the full name doesn't fit the 150 pt pill)); the mic and the menu check mark follow from the `startOnVoice` config observer for every path, Settings included. Every path ends in `Orchestrator.startOnVoiceSettingsChanged`: turning the setting off while a recording auto-start started runs cancels it like the second cancel press (`cancelOutright`: audio discarded, no transcription or paste, indicator hidden, Gemini Live socket closed, music resumed), also when it lands while that recording is still starting; a hotkey recording keeps going. The Orchestrator keeps the current recording's `RecordingOrigin` (Core: hotkey / voice, `isCancelled(startOnVoice:)` holds the rule). While idle the mic stays open in `AudioRecorder` listening mode (no WAV, last `Constants.voiceStartPreRoll` 1.5 s kept in a ring in `CaptureContext`); `VoiceStartDetector` runs FluidAudio's streaming Silero VAD (own `SharedVadModel`, ~2 MB, works with every engine) over 256 ms chunks into `SpeechOnsetGate` (VAD p >= 0.85 AND chunk RMS >= max(0.01, 3x noise floor from non-speech chunks), 2 chunks in a row). On fire the Orchestrator starts a normal recording on the already-open mic (no warmup), pre-roll first in the WAV and the Gemini Live sink; the toggle hotkey ends it. `refreshVoiceStart` re-arms after every dictation, cancel or failure, and on setting/input-device change; AppDelegate closes the mic while the screen is locked or the Mac sleeps. Never prompts for the mic (arms only if already granted). Debug builds log each speech-ish chunk (`Start on voice: p=… rms=… need=…`) for tuning the gate.
- Say a stop word to stop (`Config.stopOnOver`, Settings > Recording > Start and stop, off by default): the recording's stop words are picked at recording start from the words file's `stop words` section (selected language: `all` + its list, auto: every list; defaults "over" + Portuguese "câmbio") into a `StopWordMatcher`, then the live transcript (Parakeet previews, Gemini Live interims) feeds `StopWordWatcher`. A stop word (one or more words) matches only at the very end of the transcript, case and diacritic insensitive, on word boundaries (words are runs of non-whitespace, non-punctuation characters, so "takeover" never matches "over"; a phrase matches with any whitespace/punctuation between its words; the longest matching phrase wins). With Gemini Live the stop words are also appended to the session's custom vocabulary (after the vocabulary terms, deduplicated, within the 1,000 cap). Parakeet confirms on two previews in a row ending with one (the second covers the pause), Gemini Live on 1 s with no new text. The Orchestrator then stops as if the hotkey was pressed and strips the word (plus a tying comma/dash/semicolon/colon) from the final text with the same matcher before history/paste; existing auto-submit settings decide the Enter. whisper and batch Gemini have no live transcript, so it does nothing there: Core `TranscriptionEngine.hasLiveTranscript` (Parakeet, Gemini Live) decides, the Orchestrator listens only then, and Settings > Recording disables the toggle on the other engines (stored value kept) with a visible reason naming Parakeet and Gemini Live (`stopWordUnavailableReason`). The Stop words row under the toggle (words in effect like `over, câmbio (Portuguese)`, language words with the language name, plus an Edit… button for `words.yml`) shows only while the toggle is on and the engine has a live transcript; no other page shows stop words.
- Updates: Sparkle (SPM, pinned `exactVersion`, app target only) through `AppUpdater` (`.shared`, app target). Feed `Constants.updateFeedURL` = `appcast.xml` of the latest GitHub release, so every release uploads one next to its DMG; the DMG is the update archive. Info.plist (project.yml) holds `SUPublicEDKey` and turns on `SUVerifyUpdateBeforeExtraction` + `SURequireSignedFeed`: the archive and the appcast must both be EdDSA-signed by the matching private key. Daily automatic checks on by default; a scheduled find while the app isn't focused is a gentle reminder (status menu item "Update to X", Settings line), never a window popping up. Settings > General > Updates: Version, "Check for updates automatically", "Install updates automatically" (Sparkle's `automaticallyDownloadsUpdates`, installs at the next quit, disabled while checks are off), Check Now / Install…; status menu "Check for Updates" (`UpdateMenuState`). Dev builds have no feed (Updates shows only the version and the menu item is hidden) unless the `updateFeedURL` default is set (`defaults write io.binarygap.whisper-native.dev updateFeedURL <url>`), for testing against a local appcast.
- MusicPause (local SPM package `Packages/MusicPause`, linked by the app target, `swift test` inside it): `MusicPauser` pauses Apple Music over ScriptingBridge at recording start (before the mic opens) and resumes it as soon as the mic stops (stop, cancel, recording failure), only if it paused it and Music is still paused. Apple Events run on a private serial queue (the first one blocks on the Automation prompt). Never messages Music when it isn't running (that would launch it). Gated by `Config.pauseMusicWhileRecording` (Settings > Recording > Feedback, off by default); needs the `automation.apple-events` entitlement + `NSAppleEventsUsageDescription` (project.yml). Automation grants are per signing identity like Accessibility (see the TCC note below).
- Hotkeys: HotkeyManager via KeyboardShortcuts SPM (sindresorhus/KeyboardShortcuts): toggle dictation (tap a modifier or a chord) + cancel, user-customizable, persisted by the package. With Fn as the toggle key, `ToggleDictationControls` (Settings > Hotkeys and onboarding) shows an orange line + "Open Keyboard Settings" while the Globe key action (`GlobeKeyAction`, Core: `AppleFnUsageType` in `com.apple.HIToolbox`, re-read every second while visible) isn't "Do Nothing". A missing Accessibility grant is logged once at info level per untrusted stretch. `toggleStartOnVoice` (Control+Option+V) turns auto-start when you speak on/off (see Auto-start when you speak). `cycleLanguage` (Option+Tab) advances `selectedLanguage` through `Config.activeLanguages` (persisted under the `cycleLanguages` key): the user's active languages, in the order added, default auto + system language. Settings > Language (`LanguageTab` hosting `LanguageControls`, also the onboarding language step) shows the transcription language picker first (in Settings with a secondary line under it for the active engine, `EngineChoice.languageCaption`: whisper uses the picked language, Parakeet only narrows the alphabet, Gemini sends it as a hint; onboarding shows the Parakeet and Gemini lines in its footer), then lists them as "Your languages" with a remove button each (the last one stays), adds more through a search field (`ActiveLanguages.addable`: name or code, case/diacritic-insensitive), and the transcription language picker offers only them; removing the selected one moves the selection to the first active, and decoding appends the selected language when missing (`ActiveLanguages.normalized`). `Language` is a struct keyed by whisper codes, unknown codes decode to auto. Language is read at request time, so cycling mid-recording applies to the in-flight dictation.
- TextInsertion: TextInserter. `InsertionPlan.make` decides the route from Output settings + focus at recording start: "Copy to clipboard" (`autoPasteWhenSameApp` off) only copies, iTerm2 included, so no auto-submit fires. Auto-submit: iTerm2 sessions get Enter through ItermBridge (`Config.autoSubmitInTerminal`); any other auto-paste gets a modifier-free Return 0.15 s after Cmd+V (`TextInserter.pressReturn`, `Config.autoSubmitInOtherApps`). Esc once during a recording skips both. The iTerm2 path types the text (`iterm_helper.py`), so when the session's foreground job is a shell or ssh (`SHELL_JOBS`, iTerm2's `jobName`) it joins the lines with spaces, else each newline (line wrapping, audio tags) would run a command; other programs (Claude Code) get the newlines.
- UI: LanguageHUD — transient bottom-center pill (above the RecordingIndicator glow band) confirming the language after a cycle, or the auto-start state ("Auto-start" under ON/OFF) after the menu item or its hotkey toggles it. Window alpha is set directly, never animated in: alphaValue animations on this LSUIElement app's windows silently skip, leaving the window on screen at alpha 0.
- UI: LiveTranscriptPill — transcript while recording with Parakeet or Gemini Live, placed once at recording start by `TextInputLocator` (AX: caret rect -> small focused element -> focused window bottom -> screen bottom-center), on whichever side of the line has more room, left edge fixed; it grows with the text and drops the oldest words only once it runs out of screen. iTerm2 exposes the caret rect. Orchestrator re-reads the growing WAV (`WavWriter.readGrowingSamples`) every 0.7s and runs `ParakeetBackend.transcribePreview` (no VAD); with Gemini Live the socket's interim/final events update it instead (no re-read loop). The pasted text still comes from the full pass (or the live finals) at stop. LanguageHUD sits one window level above it.
- Settings: SettingsStore, SettingsWindowController (SwiftUI sidebar; `SettingsSection` lists the pages: General (engine picker with Whisper / Parakeet / Gemini, launch at login, Dock icon), Language (transcription language + engine line, your languages, add-language search), Recording (Input section: microphone, voice processing toggle (+ a secondary line while auto-start when you speak is also on); Start and stop section: "Auto-start when you speak" toggle, stop word toggle (disabled with a reason on engines without a live transcript) + stop words line with Edit… (only while the toggle is on), timeout `Config.recordingTimeoutSeconds`, which `AudioRecorder` reads at recording start, clamped 10-600 s, shown as "2 min" / "1 min 30 s" (`RecordingTimeoutFormat`) with an orange line while Gemini after recording is the engine and the value exceeds its ~7 min cap; Feedback section: sound feedback, recording indicator, pause music), Output (Accessibility warning while paste is selected without the grant, an "After transcribing" picker (Paste into the active app / Copy to clipboard), auto-submit (both toggles disabled with a visible reason, values kept, while "Copy to clipboard" is selected: `InsertionPlan.autoSubmitUnavailableReason`; the other-apps help names the configured cancel key), line formatting including "Wrap in <audio> tags"), Hotkeys (Accessibility warning, or a green "Accessibility granted" line when it is fine (a secondary "not granted, not needed" line with a Check button otherwise), `AccessibilitySection` shared with Output, fed by `HotkeyManager.accessibilityGranted` / `modifierToggleAvailable` through Core `InsertionPlan.accessibilityWarningShown` / `pasteNeedsAccessibility`; the same rule drives the sidebar badge and the status menu item), then an "Engines" group with one page per engine, each editable whatever engine is active and marked with a green dot in the sidebar when active: Whisper (`WhisperPage`, in order: whisper models + models directory (orange "No model in use" line while Whisper is active without one), initial prompt, translate, custom vocabulary (`VocabularySection`, see Backend), voice calibration (Record/Play sample controls and the sentence first, then the toggle, disabled with "Record a sample first." until a sample exists), then an Advanced section: server status + Start/Stop wired to the status menu's toggle via `onToggleServer`, and the VAD model row ("Silence detection (Whisper)"; Parakeet's is "Voice detection (Parakeet)" and also backs auto-start when you speak, which its help says); the server pill and Start/Stop tooltip come from Core `WhisperServerDisplay`: neutral grey "Not running, Whisper isn't the active engine" while another engine is active, red "Stopped" only while Whisper is active), Parakeet (`ParakeetPage`: a secondary "Parakeet doesn't support custom vocabulary." line under the activation row, then its two FluidAudio models + load state), Gemini (`GeminiPage`, both Gemini engines, in order: one "Gemini" activation row (disabled without an API key) + a Delivery choice, Live (streaming) / After recording (batch) (`GeminiDeliveryPicker`, also on the onboarding engine step), `Config.geminiStreaming`, which follows the last Gemini engine selected and switches the active engine when Gemini is in use, then Text style (Smart cleanup / Verbatim) right below it only while Live is chosen, then a secondary "Billed per use by Google" line; API key; custom vocabulary, the `vocabulary` section of `words.yml`). Every page keeps explanatory text behind "?" popovers (`InfoButton`, or `InfoLabel` = title + button, in DesignSystem.swift) next to the section header or row label, never in footers or captions (the Language page's one-line engine line under the picker is the exception); `LabeledToggle` and `PathField` render their help that way. Status and warning text (download state, errors, orange/red lines) stays visible. `EngineActivationRow` heads each engine page, its "?" holding the engine's `caption` (the Gemini page passes both Gemini engines); on an inactive engine's page its "Dictation currently uses X." line is secondary text, since an inactive engine is a normal state. Every model list (whisper models via `ModelListControls`, whisper VAD via `VadModelControls`, Parakeet via `ParakeetModelControls`) renders the shared `ModelRow`: name (optional "Recommended" chip and hint line), size (real once on disk, approximate before), state (not downloaded / downloading with progress / downloaded / in use) and Download or Delete, plus a Use button on downloaded, not-in-use rows of lists that pick one model (whisper models, whisper VAD; Parakeet has none). Finishing a download never selects the model (`ModelSectionState.download` vs `use`); only the prompt-confirmed `downloadDefaults` does. Whisper models list smallest first (`ModelManager.listItems`: catalog approx bytes, extras by file size), each catalog model with a speed/accuracy `hint`, large-v3-turbo (`Constants.defaultModelFileName`) marked recommended. A user-started download (model rows, the prompt) that finishes while the app isn't frontmost posts a macOS notification "<model> downloaded" (`DownloadNotifier`, app target; asks for notification permission the first time one is posted, nothing while the app is frontmost or after a denial). Delete asks via `confirmationDialog` and is disabled with a tooltip for the model in use (selected whisper model, selected VAD, Parakeet models while Parakeet is the active engine or loaded, its Silero VAD also while auto-start when you speak is on). File-level rules live in Core `ModelStorage` (downloaded check, in-use reasons, size, delete) and `ParakeetModelKind` (folders named by FluidAudio's `Repo.parakeetV3` / `Repo.vad` `folderName` under `~/Library/Application Support/FluidAudio/Models`)), StatusMenuBuilder (NSStatusItem menu; the button title carries the current language code, kept in sync from `store.$config` so hotkey and picker both update it).
- Onboarding: `OnboardingWindowController` hosting `OnboardingView`, a SwiftUI window that pages through the steps defined by `OnboardingStep` (Core: welcome, engine & model (the three `EngineChoice` engines; a Gemini section with mode + key field shows while Gemini is chosen, or below the chosen engine's section when no key existed as the step opened), permissions, hotkeys, language, audio tags, more in Settings, done). Shown at launch while `Config.needsOnboarding` (`onboardingCompletedVersion < Onboarding.currentVersion`; bump `currentVersion` to reshow it to everyone), and reopenable any time from the status menu's "Setup Guide" item. The done step shows an orange line while Whisper is the engine with no model on disk (or still downloading), saying the download prompt comes after Finish. Skip (on any step but the last) and Finish both mark the current version completed; every control writes straight to `store.config`, so a partial run keeps whatever was changed. The more-in-Settings step (`MoreInSettingsStepView`) only names the features the earlier steps don't set up, one line each, grouped by the Settings page that holds them; a new feature gets a line there instead of its own step. The hotkeys step lists, under "Anytime", the paste last transcript, cycle language and "Toggle auto-start when you speak" shortcuts as recorder fields showing the configured keys. Step views reuse `ModelListControls`, `LanguageControls`, `ToggleDictationControls` and `ParakeetModelControls` from the Settings pages, so onboarding and Settings edit the same config through the same code. `PermissionsState` polls microphone authorization and `AXIsProcessTrusted()` while the permissions step is visible.

## Build / run
- `mise run generate` — xcodegen generate (also resolves SPM deps). `ai:build`/`ai:test` do not regenerate: run it after adding or deleting Swift files, else the new symbols are "not in scope".
- `mise run ai:build` / `mise run ai:test` — agent-facing variants. Use these, not the bare `build`/`test` tasks.
- `mise run ai:run` — build (summarized) + open the .app built from this checkout (`scripts/open-debug-app.sh` matches DerivedData on `WorkspacePath`). Editing `mise.toml` forces a whisper.cpp rebuild (it is in `whisper:build`'s sources), which needs cmake (see below). On a Mac without an Apple Development cert it fails at signing; build ad-hoc with `xcodebuild -project WhisperNative.xcodeproj -scheme WhisperNative -configuration Debug build CODE_SIGN_IDENTITY=- DEVELOPMENT_TEAM=` to check compilation.
- Missing cmake / "tapi error: malformed file" on `whisper:build`: the build needs cmake, which then picks the Command Line Tools SDK that Xcode's linker can't read. Fix: install cmake and point `SDKROOT` at Xcode's SDK (`SDKROOT=$(xcrun --sdk macosx --show-sdk-path) mise run ai:test`).
- Built app: `~/Library/Developer/Xcode/DerivedData/WhisperNative-*/Build/Products/Debug/WhisperNative.app`. Worktrees get their own DerivedData dir: pick the one whose `info.plist` `WorkspacePath` is this checkout's `WhisperNative.xcodeproj`.
- App logs: `~/Library/Logs/whisper-native/` (dev app: `whisper-native-dev/`).

## whisper.cpp build + bundling
- Source cloned + built by mise, never checked in. `mise run whisper:fetch` shallow-clones `ggerganov/whisper.cpp` at the pinned `WHISPER_CPP_TAG` (mise.toml env, currently v1.9.1) into gitignored `external/whisper.cpp/`; `whisper:build` runs cmake (Release, `GGML_METAL=ON`, `WHISPER_COREML=OFF`) producing `external/whisper.cpp/build/bin/whisper-server` + its dylibs. `ai:build`/`build` depend on `whisper:build`; `generate` depends on `ai:whisper:build`, since xcodegen lists the staged dylibs at generation time.
- v1.9.1 whisper-server is NOT static: it links `libwhisper` + five `libggml*` dylibs via `@rpath` (Metal shaders are embedded in `libggml-metal` via `GGML_METAL_EMBED_LIBRARY`, so no external `.metallib`).
- `whisper:build` then runs `scripts/stage-whisper-server.sh`, which stages `external/whisper.cpp/build/bundle/`: `whisper-server` with its rpath swapped to `@executable_path/../Frameworks`, plus the transitive `@rpath` dylib closure in `bundle/Frameworks/` as real files named by install name (`libwhisper.1.dylib`, no symlinks) with an `@loader_path` rpath. project.yml embeds them through Xcode Copy Files phases with `CodeSignOnCopy`: the binary into `Contents/MacOS`, the dylibs into `Contents/Frameworks`. Xcode signs them and re-seals the app whenever they change. Never modify bundle contents from a run script: Xcode skips re-sealing the app on incremental builds, leaving `codesign --verify` failing with "a sealed resource is missing or invalid".
- `WhisperServerManager.resolveBinaryPath()`: `WHISPER_SERVER_BINARY` env override -> bundled `Contents/MacOS/whisper-server` (`Bundle.main.url(forAuxiliaryExecutable:)`) -> Debug-only dev fallback `<repo>/external/whisper.cpp/build/bin/whisper-server`, `<repo>` derived from `#filePath` at compile time (walks up from the source file to the repo root), so it resolves to whichever checkout this was compiled from. Release builds skip it so the shipped binary holds no checkout path; `whisper:build` passes `-ffile-prefix-map` for the same reason (cmake bakes `__FILE__` into the dylibs).

## Runtime dependencies (models overridable in Settings)
- Models default dir: `~/Library/Application Support/whisper-native/models/` (App Support, `Constants.defaultModelsDirectory`). Settings scans this folder for `.bin` files (`ModelManager.availableModels`, silero excluded from the whisper-model picker). User can point at a different folder.
- Models download on demand from HuggingFace: whisper models from `ggerganov/whisper.cpp` (the recommended `ggml-large-v3-turbo.bin` through `ModelSectionState.downloadDefaults` once the user accepts the "Download a Whisper model?" prompt, see Engine switch) + VAD `ggml-silero-v6.2.0.bin` (`ggml-org/whisper-vad`), fetched with the first whisper model. Every download URL pins a Hugging Face commit, and the file must match the catalog's exact size and SHA-256 (`ModelDownload`) before it replaces anything; any failure or cancel deletes the `.partial` file. Bumping a model means updating the revision, size and hash together. Download w/ progress in the model rows on the Settings > Whisper page and the onboarding engine step. While the onboarding window is open nothing is asked (the engine & model step shows its own download state); the check runs on Finish/Skip (after History opens, so the prompt is a sheet on it). A download the user starts that lands the selected-but-missing model while Whisper is active starts the daemon (AppDelegate's `$isDownloading` observer).
- Changing the selected model/VAD in Settings reloads the server: AppDelegate observes `store.$config` (modelPath/vadModelPath), calls `WhisperServerManager.reload` (rewrites plist + re-bootstraps launchd). Skips reload if the model file isn't readable.
- server: `127.0.0.1:8080`, `GET /health` -> `{"status":"ok"}`, transcribe via `POST /inference` (multipart wav + language/vad/etc params, returns `{"text":...}`).
- Needs mic + accessibility TCC permissions (accessibility for CGEvent paste/typing). `HotkeyManager.startAccessibilityPoll` runs while the grant is missing (whatever the toggle key) and picks it up live, no relaunch.
- TCC keys accessibility on bundle id + code-signing requirement. The dev app has its own bundle id, so it gets its own row and grants. Two builds under ONE bundle id with different certs (e.g. a locally signed build and the Developer ID release) are DIFFERENT clients under one row: System Settings shows a single checked "WhisperNative" while the running copy is untrusted, mic works, `CGEventPost` of Cmd+V is silently dropped, nothing pastes. Fix with `tccutil reset Accessibility io.binarygap.whisper-native` and re-grant. Inspect with `sudo sqlite3 "/Library/Application Support/com.apple.TCC/TCC.db" "select service, auth_value, hex(csreq) from access where client like '%whisper%';"` — the csreq names the cert the grant is bound to. SIP blocks writing that db even as root; flip the toggle in the UI.

## Accessibility testing
- Anything needing AX or paste (text-input anchoring, Cmd+V) must be tested on a build that holds the accessibility grant: an ad-hoc Debug build has no accessibility grant, so AX queries and paste silently fail there.

## Conventions
- Code/comments English only. Default dictation language auto-detect; any whisper.cpp language selectable.
- To tear down the dev daemon for testing: `launchctl bootout gui/$(id -u)/io.binarygap.whisper-server.dev; launchctl disable ...; pkill -9 -f "DerivedData/.*whisper-server"` (KeepAlive respawns it otherwise; a bare `pkill -f whisper-server` also kills the installed Release copy's server). Label `io.binarygap.whisper-server` (dev: `.dev`), plist at `~/Library/LaunchAgents/<label>.plist`; the app rewrites it to its own bundled binary on every launch.
