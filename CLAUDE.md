# whisper-native

Native macOS Swift port of the Hammerspoon whisper dictation tool: always-on menu-bar agent that records mic, transcribes via a local whisper.cpp server daemon, and inserts text into the focused app.

## Architecture
- Menu-bar agent app (`LSUIElement=true`, no dock icon). SwiftUI `@main` + `AppDelegate`. App target `WhisperNative`, bundle id `io.binarygap.whisper-native` (Binary Gap LLC).
- Dev app: the Debug config builds "WhisperNative Dev" (`io.binarygap.whisper-native.dev`, project.yml `configs.debug`), so it runs next to the installed Release copy in `/Applications`. Separate bundle id = separate TCC grants, UserDefaults (settings, hotkeys, onboarding) and menu bar item. `Constants.isDevBuild` (`#if DEBUG`, so tests get the dev values too) splits the rest: daemon label `io.binarygap.whisper-server.dev` on port 8081, data `~/Library/Application Support/whisper-native-dev/` (history, tmp, calibration), logs `~/Library/Logs/whisper-native-dev/`, Keychain service `io.binarygap.whisper-native.dev.gemini`. The models folder (`whisper-native/models`) is shared. Paths and names elsewhere in this file are the Release values. Both copies start with the same default hotkeys, so while both run give the dev app its own toggle hotkey.
- Built with xcodegen (`project.yml` is source of truth; `WhisperNative.xcodeproj` is generated + gitignored). Tasks via mise.
- Pipeline: global hotkey -> `AudioRecorder` (AVAudioEngine -> 16kHz mono 16-bit PCM wav) -> `WhisperClient` (HTTP multipart POST to local server) -> `TextInserter` (pasteboard+Cmd-V w/ restore, CGEvent typing fallback). Orchestrated in `Sources/WhisperNative/App/`.
- Whisper server is an always-on DAEMON, not a child process: `WhisperServerManager` installs a launchd plist and `launchctl bootstrap`s it. Server persists across app restarts (warm model = the whole point). App boots it out on Quit (`stopServer` wired in AppDelegate). plist has KeepAlive, so it respawns until explicitly booted out + disabled.

## Modules
Source dirs group by target under `Sources/<target>/<module>/`. App target (`WhisperNative`): App, Hotkeys, Settings, Onboarding. Framework target (`WhisperNativeCore`): Shared, Server, Backend, Audio, TextInsertion, UI. This mirrors the two-target split and renders as two parent groups in Xcode.
- Shared: Models, Config (UserDefaults-backed, all settings), Constants (paths/ports), AppError, FileLogger.
- History: `TranscriptionHistoryStore` writes `~/Library/Application Support/whisper-native/history/history.json`, the newest `Constants.maxHistoryItems` (5000) dictations kept as a usage log for debugging and model comparisons (text, language, model, timestamp, response time `durationSeconds`, `audioDurationSeconds`, Gemini Live mode `transcriptionMode` (nil for other engines and for reruns, which go through the batch model and record `GeminiBackend.modelID`), `estimatedCostUSD` (Gemini models only, nil for local engines: `GeminiPricing` list price x 25 audio tokens/s in + transcript chars/4 out, since Live never reports usage; a rerun replaces it with the rerun's cost; failed batch runs aren't billed, failed Live runs are)); only the newest `Constants.maxHistoryAudioFiles` (50) entries keep their WAV, older WAVs are deleted on the next add. The History window lists the newest `maxHistoryDisplayedItems` (100) matches; search runs over all entries.
- Server: WhisperServerManager (launchd bootstrap/bootout, health, model hot-swap via POST /load), LaunchdManager, ServerPlist.
- Backend: WhisperClient + TranscriptionBackend protocol, MultipartFormData. ParakeetBackend (`.shared` actor): Parakeet TDT v3 in-process via the FluidAudio SPM package (Apache-2.0, pinned `exactVersion` in project.yml), Silero VAD first, output through FillerRemover (drops uh/hmm; "um" only for non-Portuguese text since it's the pt article). "Wrap lines" / "Sentence per line" apply to Parakeet too: whisper wraps server-side (`max_len`), Parakeet through `LineWrapper`. Models download to `~/Library/Application Support/FluidAudio/Models` on first load (~20s first load, then ~0.05-0.5s per dictation).
- Backend (experimental): GeminiBackend (`.shared` actor) sends the finished WAV inline (base64) to `gemini-3.5-transcribe` via `POST v1beta/interactions` with `store: false` (no server-side retention); fixed language goes as a `language_codes` hint, auto sends none. Same FillerRemover/LineWrapper post-processing as Parakeet, no live preview, no segments. ~2s per dictation; inline cap ~7 min of audio (20 MB request); key limited to ~10 requests/min. Key in the Keychain (`GeminiAPIKeyStore`, service `io.binarygap.whisper-native.gemini`, edited via `GeminiAPIKeyField` in Settings and onboarding), `GEMINI_API_KEY` env as fallback; never in Config or logs. Live test `GeminiBackendTests.testLiveTranscriptionOfSpokenWav` runs only with the key plus `GEMINI_BILLED_TESTS=1` (`BilledGeminiTests.apiKey()`; every other test uses stubs and never reaches the network): `fnox exec -- sh -c 'TEST_RUNNER_GEMINI_BILLED_TESTS=1 TEST_RUNNER_GEMINI_API_KEY="$GOOGLE_GENAI_API_KEY" xcodebuild -scheme WhisperNativeCoreTests -configuration Debug test -only-testing:WhisperNativeCoreTests/GeminiBackendTests'`. Every Gemini call is billed: no exploratory or repeated API requests (list-models, retries, reruns of the live test) unless the change touches the request path; answer API questions from docs or earlier responses first.
- Backend (experimental): Gemini Live streams audio while recording to `gemini-3.5-transcribe-live` over the Live API WebSocket (`BidiGenerateContent`, key in the `x-goog-api-key` header so the URL is loggable). `GeminiLiveProtocol` (message encode/decode, whisper code -> BCP-47 hint: auto sends `[]`, a fixed language its code with the system region's variant when Gemini lists one, e.g. pt -> pt-BR/pt-PT, languages Gemini lacks send `[]`), `GeminiLiveSession` (one socket per dictation, serial queue: connect + setup at recording start with manual VAD, PCM buffered until `setupComplete` then `activityStart` + 100 ms chunks, stop sends `activityEnd` and waits for the finals + `generationComplete`; the server sends no `turnComplete`; the client closes with 1000 right after generationComplete since the server never closes on its own or sends anything after it, and the API dashboard counts every such client-ended stream as a 409 ABORTED, which is expected and harmless), `GeminiLiveBackend` (5 s final timeout; on connect error, socket drop, timeout or no key it falls back to ONE batch `GeminiBackend` call on the WAV; cancel closes the socket with no activityEnd and no fallback; same post-processing via `GeminiBackend.postProcess`). Interims are cumulative per segment and drive LiveTranscriptPill. `AudioRecorder.pcmSink` hands the tap's converted buffers to the session (the WAV still gets them all). Mode setting `Config.geminiLiveMode` (Smart default / Verbatim), shown only for this engine; `Config.prompt` is unused. Language is fixed at recording start (cycling mid-recording reaches only a fallback call). One log line per dictation: openMs, setupMs, stopToFinalMs, audioSeconds, interim/final counts, fallback yes/no + reason. Debug builds also log `Gemini Live usage:` (mode, prompt/response/thoughts tokens, estimated USD at list price) if `usageMetadata` arrives before the socket closes (this model has never sent it, so Live cost is estimated from audio seconds) and any unhandled server message keys; Release logs neither. History rerun uses the batch model. Live test (billed, run only when the streaming path changes): `fnox exec -- sh -c 'TEST_RUNNER_GEMINI_BILLED_TESTS=1 TEST_RUNNER_GEMINI_API_KEY="$GOOGLE_GENAI_API_KEY" xcodebuild -scheme WhisperNativeCoreTests -configuration Debug test -only-testing:WhisperNativeCoreTests/GeminiLiveSessionLiveTests'`.
- Engine switch (`Config.transcriptionEngine`, Settings > General): selecting Parakeet boots the whisper daemon out and preloads Parakeet; selecting Gemini or Gemini Live boots the daemon out and unloads Parakeet; switching back unloads Parakeet and re-bootstraps whisper. Parakeet and both Gemini engines skip the whisper health check, prompt and voice calibration. Parakeet auto-detects, and the selected language only picks its script token filter (`ParakeetBackend.tokenFilterLanguage`: FluidAudio-supported language passes through; auto/unsupported gets the Latin filter when the system language is Latin-script, else none).
- Audio: AudioRecorder, WavWriter, RecordingIndicator.
- MusicPause (local SPM package `Packages/MusicPause`, linked by the app target, `swift test` inside it): `MusicPauser` pauses Apple Music over ScriptingBridge at recording start (before the mic opens) and resumes it as soon as the mic stops (stop, cancel, recording failure), only if it paused it and Music is still paused. Apple Events run on a private serial queue (the first one blocks on the Automation prompt). Never messages Music when it isn't running (that would launch it). Gated by `Config.pauseMusicWhileRecording` (Settings > General > Behavior, off by default); needs the `automation.apple-events` entitlement + `NSAppleEventsUsageDescription` (project.yml). Automation grants are per signing identity like Accessibility (see the TCC note below).
- Hotkeys: HotkeyManager via KeyboardShortcuts SPM (sindresorhus/KeyboardShortcuts): toggle dictation (tap a modifier or a chord) + cancel, user-customizable, persisted by the package. `cycleLanguage` (Option+Tab) advances `selectedLanguage` through `Config.cycleLanguages` (user-picked subset of whisper.cpp languages, default auto + system language; `Language` is a struct keyed by whisper codes, unknown codes decode to auto); language is read at request time, so cycling mid-recording applies to the in-flight dictation.
- TextInsertion: TextInserter. Auto-submit: iTerm2 sessions get Enter through ItermBridge (`Config.autoSubmitInTerminal`); any other auto-paste gets a modifier-free Return 0.15 s after Cmd+V (`TextInserter.pressReturn`, `Config.autoSubmitInOtherApps`). Esc once during a recording skips both.
- UI: LanguageHUD — transient bottom-center pill (above the RecordingIndicator glow band) confirming the language after a cycle. Window alpha is set directly, never animated in: alphaValue animations on this LSUIElement app's windows silently skip, leaving the window on screen at alpha 0.
- UI: LiveTranscriptPill — transcript while recording with Parakeet or Gemini Live, placed once at recording start by `TextInputLocator` (AX: caret rect -> small focused element -> focused window bottom -> screen bottom-center), on whichever side of the line has more room, left edge fixed; it grows with the text and drops the oldest words only once it runs out of screen. iTerm2 exposes the caret rect. Orchestrator re-reads the growing WAV (`WavWriter.readGrowingSamples`) every 0.7s and runs `ParakeetBackend.transcribePreview` (no VAD); with Gemini Live the socket's interim/final events update it instead (no re-read loop). The pasted text still comes from the full pass (or the live finals) at stop. LanguageHUD sits one window level above it.
- Settings: SettingsStore, SettingsWindowController (SwiftUI), StatusMenuBuilder (NSStatusItem menu; the button title carries the current language code, kept in sync from `store.$config` so hotkey and picker both update it).
- Onboarding: `OnboardingWindowController` hosting `OnboardingView`, a SwiftUI window that pages through the steps defined by `OnboardingStep` (Core: welcome, engine & model, permissions, hotkeys, language, audio tags, done). Shown at launch while `Config.needsOnboarding` (`onboardingCompletedVersion < Onboarding.currentVersion`; bump `currentVersion` to reshow it to everyone), and reopenable any time from the status menu's "Setup Guide…" item. Skip (on any step but the last) and Finish both mark the current version completed; every control writes straight to `store.config`, so a partial run keeps whatever was changed. Step views reuse `ModelListControls`, `LanguageControls` and `ToggleDictationControls` extracted from the Settings tabs, so onboarding and Settings edit the same config through the same code. `PermissionsState` polls microphone authorization and `AXIsProcessTrusted()` while the permissions step is visible.

## Build / run
- `mise run generate` — xcodegen generate (also resolves SPM deps). `ai:build`/`ai:test` do not regenerate: run it after adding or deleting Swift files, else the new symbols are "not in scope".
- `mise run ai:build` / `mise run ai:test` — agent-facing variants (see `~/.claude/rules/mise-conventions.md`). Use these, not the bare `build`/`test` tasks.
- `mise run ai:run` — build (summarized) + open the .app built from this checkout (`scripts/open-debug-app.sh` matches DerivedData on `WorkspacePath`). Editing `mise.toml` forces a whisper.cpp rebuild (it is in `whisper:build`'s sources), which needs cmake (see below). After making code changes, run this and tell the user the build is updated and running. On a Mac without an Apple Development cert it fails at signing; build ad-hoc with `xcodebuild -project WhisperNative.xcodeproj -scheme WhisperNative -configuration Debug build CODE_SIGN_IDENTITY=- DEVELOPMENT_TEAM=` to check compilation.
- `No signing certificate "Mac Development" found`: the Apple Development identity is missing from the login keychain (e.g. after a machine restore). Maintainers pull it read-only with fastlane match (`type:development platform:macos readonly:true skip_provisioning_profiles:true`, run with the release secrets in the environment).
- Missing cmake / "tapi error: malformed file" on `whisper:build`: cmake isn't installed system-wide and, when present, picks the Command Line Tools SDK that Xcode's linker can't read. Fix with `SDKROOT=$(xcrun --sdk macosx --show-sdk-path) nix shell nixpkgs#cmake -c mise run ai:test` (e.g. via nix), or install cmake and point `SDKROOT` at Xcode's SDK.
- Built app: `~/Library/Developer/Xcode/DerivedData/WhisperNative-*/Build/Products/Debug/WhisperNative.app`. Worktrees get their own DerivedData dir: pick the one whose `info.plist` `WorkspacePath` is this checkout's `WhisperNative.xcodeproj`.
- App logs: `~/Library/Logs/whisper-native/` (dev app: `whisper-native-dev/`).

## whisper.cpp build + bundling
- Source cloned + built by mise, never checked in. `mise run whisper:fetch` shallow-clones `ggerganov/whisper.cpp` at the pinned `WHISPER_CPP_TAG` (mise.toml env, currently v1.9.1) into gitignored `external/whisper.cpp/`; `whisper:build` runs cmake (Release, `GGML_METAL=ON`, `WHISPER_COREML=OFF`) producing `external/whisper.cpp/build/bin/whisper-server` + its dylibs. `ai:build`/`build` depend on `whisper:build`; `generate` depends on `ai:whisper:build`, since xcodegen lists the staged dylibs at generation time.
- v1.9.1 whisper-server is NOT static: it links `libwhisper` + five `libggml*` dylibs via `@rpath` (Metal shaders are embedded in `libggml-metal` via `GGML_METAL_EMBED_LIBRARY`, so no external `.metallib`).
- `whisper:build` then runs `scripts/stage-whisper-server.sh`, which stages `external/whisper.cpp/build/bundle/`: `whisper-server` with its rpath swapped to `@executable_path/../Frameworks`, plus the transitive `@rpath` dylib closure in `bundle/Frameworks/` as real files named by install name (`libwhisper.1.dylib`, no symlinks) with an `@loader_path` rpath. project.yml embeds them through Xcode Copy Files phases with `CodeSignOnCopy`: the binary into `Contents/MacOS`, the dylibs into `Contents/Frameworks`. Xcode signs them and re-seals the app whenever they change. Never modify bundle contents from a run script: Xcode skips re-sealing the app on incremental builds, leaving `codesign --verify` failing with "a sealed resource is missing or invalid".
- `WhisperServerManager.resolveBinaryPath()`: `WHISPER_SERVER_BINARY` env override -> bundled `Contents/MacOS/whisper-server` (`Bundle.main.url(forAuxiliaryExecutable:)`) -> Debug-only dev fallback `<repo>/external/whisper.cpp/build/bin/whisper-server`, `<repo>` derived from `#filePath` at compile time (walks up from the source file to the repo root), so it resolves to whichever checkout this was compiled from. Release builds skip it so the shipped binary holds no checkout path; `whisper:build` passes `-ffile-prefix-map` for the same reason (cmake bakes `__FILE__` into the dylibs).

## Runtime dependencies (models overridable in Settings)
- Models default dir: `~/Library/Application Support/whisper-native/models/` (App Support, `Constants.defaultModelsDirectory`). Settings scans this folder for `.bin` files (`ModelManager.availableModels`, silero excluded from the whisper-model picker). User can point at a different folder.
- First run downloads on demand from HuggingFace (`ModelSectionState.downloadDefaults`): whisper `ggml-large-v3-turbo.bin` (`ggerganov/whisper.cpp`) + VAD `ggml-silero-v6.2.0.bin` (`ggml-org/whisper-vad`). Streaming download w/ progress in GeneralTab. While the onboarding window is open this download is deferred (the engine & model step shows its own download state); it starts on Finish/Skip if the user still has no model.
- Changing the selected model/VAD in Settings reloads the server: AppDelegate observes `store.$config` (modelPath/vadModelPath), calls `WhisperServerManager.reload` (rewrites plist + re-bootstraps launchd). Skips reload if the model file isn't readable.
- server: `127.0.0.1:8080`, `GET /health` -> `{"status":"ok"}`, transcribe via `POST /inference` (multipart wav + language/vad/etc params, returns `{"text":...}`).
- Needs mic + accessibility TCC permissions (accessibility for CGEvent paste/typing). `HotkeyManager.startAccessibilityPoll` picks the grant up live, no relaunch.
- TCC keys accessibility on bundle id + code-signing requirement. The dev app has its own bundle id, so it gets its own row and grants. Two builds under ONE bundle id with different certs (e.g. an old Debug build from before the dev split, and the Developer ID copy) are DIFFERENT clients under one row: System Settings shows a single checked "WhisperNative" while the running copy is untrusted, mic works, `CGEventPost` of Cmd+V is silently dropped, nothing pastes. Fix with `tccutil reset Accessibility io.binarygap.whisper-native` and re-grant. Inspect with `sudo sqlite3 "/Library/Application Support/com.apple.TCC/TCC.db" "select service, auth_value, hex(csreq) from access where client like '%whisper%';"` — the csreq names the cert the grant is bound to. SIP blocks writing that db even as root; flip the toggle in the UI.

## Notarization
- Release tooling (fastlane, Developer ID signing, notarization) lives in the gitignored `fastlane/` folder and `mise.local.toml`, maintainers only.
- `release:install` (a `depends_post` of `mise run release`) replaces `/Applications/WhisperNative.app` (the daily copy; the Debug dev app is untouched). The user may be dictating with that copy: ask before running `release:install` or touching `/Applications/WhisperNative.app`. To build without installing, run the lane directly: `fnox run -- fastlane mac notarized_build`.
- Anything needing AX or paste (text-input anchoring, Cmd+V) must be tested on a build that holds the accessibility grant: an ad-hoc Debug build has no accessibility grant, so AX queries and paste silently fail there.

## Status / unproven
- Builds clean, launches, server daemon comes up + health-checks green (verified on machine).
- Record -> transcribe -> insert round-trip verified through the iTerm2 bridge path. The Cmd+V paste path into a non-terminal app is not smoke-tested.
- `mise run release` verified end to end: notarized, stapled, gatekeeper-accepted, installed.
- Gemini Live verified by hand (Debug build): en ~400-600 ms stop -> final, pt accurate, Smart and Verbatim same latency (Smart drops fillers and applies spoken self-corrections). Not tested by hand: cancel mid-recording, offline fallback, auto language with Portuguese, the Keychain key field UI. Known gaps: silence ends in a "Transcription returned empty text" error; language is locked at recording start.

## Conventions
- Code/comments English only. Default dictation language auto-detect; any whisper.cpp language selectable.
- To tear down the dev daemon for testing: `launchctl bootout gui/$(id -u)/io.binarygap.whisper-server.dev; launchctl disable ...; pkill -9 -f "DerivedData/.*whisper-server"` (KeepAlive respawns it otherwise; a bare `pkill -f whisper-server` also kills the daily copy). Label `io.binarygap.whisper-server` (dev: `.dev`), plist at `~/Library/LaunchAgents/<label>.plist`; the app rewrites it to its own bundled binary on every launch.
- Public repo (only `main` + release tags are on the remote). The local `private-history` branch holds pre-release history with private data: never push it.
- Pushes are leak-checked by a PreToolUse hook (`.claude/settings.local.json`); run `mise run leak-check --all` before changing visibility or rewriting history.
